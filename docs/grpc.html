gRPC: один контракт, четыре вида вызова

gRPC: one contract, four kinds of call

Свой сервис котировок валют. Его API описан в .proto-файле, сообщения идут в двоичном виде, а вызов может быть потоком в любую сторону. Тесты проверяют коды статусов, дедлайны, потоки без пропусков и сам контракт.

An FX quote service of our own. Its API is a .proto file, messages travel as binary, and a call can stream either way. The tests check status codes, deadlines, streams without gaps, and the contract itself.

Четыре вида вызова

Four kinds of call

Синие точки — сообщения клиента, бирюзовые — ответы сервера. В REST есть только первый вид.

Blue dots are client messages, teal ones server messages. REST has only the first kind.

Status codes instead of HTTP codes

gRPC has 17 codes. Dotted ones are those our service returns and the tests check. Pick a code.

Deadline

Дедлайн едет вместе с вызовом

The deadline travels with the call

Клиент говорит серверу: «ответ нужен через N мс». Если не успели, клиент получает DEADLINE_EXCEEDED, а хороший сервер бросает работу, которую уже некому вернуть.

The client tells the server “I need the answer within N ms”. If it is late, the client gets DEADLINE_EXCEEDED, and a good server drops work nobody will receive.

Поток, который не теряет обновления

A stream that loses no update

Сначала приходит снимок по каждой паре (подсвечен), потом живые цены. seq растёт ровно на 1, поэтому пропуск виден сразу. Включите баг, чтобы сервер терял каждое 10-е обновление.

A snapshot of each pair comes first (highlighted), then live prices. seq grows by exactly 1, so a gap shows at once. Turn on the bug to make the server drop every 10th update.
